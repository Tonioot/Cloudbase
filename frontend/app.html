Startup check
Before a new instance gets visitors, Cloudbase waits until it answers the way you set here. Until then it stays out of nginx, so a broken version never goes live and the old one keeps serving.

              

                

                  The address Cloudbase requests on the new instance, for example /health. Leave empty to only check that the port accepts connections.
                  
                

                

                  Which responses count as healthy: status codes (200) or classes (2xx), separated by commas. Leave empty to accept anything below 500.
                  
                

                

                  How long a new instance gets to become healthy, in seconds (10 to 3600). After that it is marked as failed, and a rolling or blue/green deploy keeps the old version live.
